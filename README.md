# Qwen3-TTS Studio

Qwen3-TTS（千问语音合成）的本地工作台：**语音克隆 / 声音设计 / 官方音色 / 剧本工坊 / 音色库 / 合成记录 / API 对接** 七个页面，
一个自带便携运行时的目录，双击即用，全离线。

界面与交互沿用 [OmniVoice Studio](../omnivoice-studio) 的设计语言（同一套颜色、圆角、阴影令牌），
但**后端是重写的** —— 见下文「相对原整合包改了什么」。

---

## 快速开始

```
双击 启动程序.bat
```

浏览器打开 **http://127.0.0.1:7867** 。首次生成要加载权重并预热 CUDA graph，慢一次（实测约 15 秒），
之后同一规格会复用。**本机实测热路径 RTF 0.66**（生成 6.4 秒音频耗时 4.2 秒，快于实时）。

想先确认环境是否正常：

```
双击 自检.bat
```

它会打印硬件档位、音色库完整性、权重就位情况。

## 命令行与 AI 上手

界面之外还有一层薄 CLI（`tools/qwen.py`），人和 AI 共用，不重复实现任何能力 ——
它只是把「组请求 → 轮询 → 把结果说清楚」收成四条子命令：

```bat
runtime\python\python.exe tools\qwen.py                    :: 探活：服务 / 权重 / 驻留模型
runtime\python\python.exe tools\qwen.py voices             :: 有哪些音色（* = 已有基因）
runtime\python\python.exe tools\qwen.py say "今天天气不错。" --voice 御姐
runtime\python\python.exe tools\qwen.py say --mode script --text - < 剧本.txt
```

`--json` 让 stdout 只输出一行 JSON（进度全在 stderr），所以能直接管道；退出码 0/1。

**`llms.txt` 是一份写给 AI 的操作手册**：先探活、再读 `/api/docs`、常用命令、
8 条「会炸的地方」（显存只容一套权重、音色名唯一 409、`xvec_only` 是每音色属性、
流式不支持剧本……）、产物在哪、哪些事不要做。它跟着整合包一起发出去 ——
所以别人把 AI 接上来时，不用先读一遍代码。

> 为什么不把接口清单写进这份手册：`GET /api/docs` 已经是**唯一权威**（还会和真实注册
> 路由对账），再抄一份必然分叉。手册只写文档里没有的东西 —— **顺序和禁忌**。

## 五个模型与四个模式

| 模式 | 权重 | 规格 | 说明 |
|---|---|---|---|
| 语音克隆 `clone` | `-Base` | 1.7B / 0.6B | 参考音频复刻音色 + 自由文本情感指令 |
| 声音设计 `design` | `-VoiceDesign` | 仅 1.7B | 用文字描述捏一个不存在的音色 |
| 官方音色 `official` | `-CustomVoice` | 1.7B / 0.6B | 9 个内置说话人（每张卡可直接试听），支持逐句情感与多人对话 |
| 剧本工坊 `script` | `-Base`（同 clone） | 1.7B / 0.6B | 多角色长剧本，逐句调音色库 |

**同一时刻只让一套权重驻留显存。** 切换模式或规格时会自动卸载上一套 ——
6 GB 显存塞不下两套 1.7B，先卸载是最省事的做法。

## 情感指令是自由文本，不是固定标签

这是本项目与你可能用过的一些 TTS 最大的区别，也是「克隆」页第 3 张卡存在的理由。

Qwen3-TTS 的 `instruct` 由内核的 `_build_instruct_text()` 包成一个对话轮次
（`<|im_start|>user\n{你的文字}<|im_end|>\n`）喂给模型，**不查任何词表**。
所以：

- 写「愤怒」和写「压着火，语速偏快，句尾咬字加重」都会被原样送进模型 —— 后者效果更好；
- 越像在给演员说戏，效果越稳；
- 留空就是中性朗读。

> **为什么原项目让你觉得「Qwen3 的情绪控制不如预期」？**
> 原整合包的 `bin/integrated_app.py`，语音克隆页的处理函数 `fn_voice_clone` 压根没有把 `instruct`
> 传下去 —— 内核明明支持（`generate_voice_clone(..., instruct=None)`），界面却没接到。
> 于是克隆模式的情感永远是空的。本工具把这条通路接上了，克隆页和剧本页都可以逐句写情感。

### 但「通路接通」只是及格线 —— 情绪怎么调才有效，实测过

（`tools/ab_emotion.py` 跑样本，`tools/measure_prosody.py` 量，`tools/emotion_report.py` 出试听页）

**先说方法，因为结论全靠它站得住。** 参数完全相同的重复生成**并不逐帧一致**，实测（连跑 6 条）：

| 指标 | 均值 ± 标准差 | 极差 |
|---|---|---|
| 时长 | 3.91 ± 0.09 s | 0.24 |
| 基频 | 108.6 ± 4.4 Hz | 11.7 |
| **音高起伏** | 22.8 ± **2.5** 半 | **7.6** |
| 能量动态 | 81.6 ± 2.2 dB | 6.6 |

所以：**只跑一两条、差两三个半音，读出来的全是噪声。** 每组至少 5 条比均值。
而且**要挑方差小的维度看** —— `音高起伏` 在所有条件下都落在 22~24 半，拿它当主指标会得出「什么都没变」的错觉。
真正响应的是 **基频水平** 和 **时长**。

按这个方法重做（同一音色·仅向量、同一句话、每组 5–6 条，看基频）：

| 条件 | 基频 | 相对基线 |
|---|---|---|
| 文本原样 + 空指令（基线） | 106.1 ± 4.1 Hz | — |
| 文本加停顿标点 + 空指令 | 114.8 ± 14.3 Hz | **+8.7 \*** |
| 文本原样 + 标签词「悲痛绝望的大喊」 | 118.6 ± 15.8 Hz | **+12.5 \*** |
| 文本原样 + 描述句 | 117.0 ± 12.9 Hz | **+10.9 \*** |
| **文本加停顿标点 + 描述句** | **148.3 ± 24.8 Hz** | **+42.2 \*** |

（\* = 差值超过基线自身标准差）

四条结论：

1. **指令是有效的。** 加指令把基频抬高约 11 Hz，稳定超过噪声。所以「写了没反应」不是通路问题。
2. **「标点」是更强的杠杆，而且和指令互相放大。** 只改标点 +8.7、只加描述句 +10.9，
   两者一起 **+42.2**，远大于相加。标点先给「可以喊、可以拖、可以停」留出位置，指令才有地方使力。
   把句号换成 `——！` / `……`，比换任何形容词都直接。
3. **写「怎么念」比写情绪名更稳。** 两者对基频的抬升差不多（+12.5 / +10.9），
   但标签词各维度离散度都更大（基频 ±15.8 对 ±12.9）—— 写「悲痛绝望的大喊」时你不知道这条会出什么样。
4. **但天花板是真实存在的 —— 而且它跟着权重走，不跟着写法走。**

### 天花板在哪：`Base` 没被训练来做指令

「有效果，但没想象的那么好」不是错觉。上游的模型表里，**「指令控制」这一列只给了
`VoiceDesign` 和 `1.7B CustomVoice`**；`Base` 那一列是**空的**。维护者关闭 issue #25 时的原话是
**「12 Hz Base 的控制不稳定，所以 Base 不支持 instruct」**。

而「语音克隆」走的正是 `Base`。本工具把 `instruct` 接进了这条路径（上游 API 里有这个参数），
所以**它有反应** —— 上表那个 +11 Hz 是实测的 —— 但这属于「让一个没为这件事训练过的权重去做这件事」：
方向对，幅度小，条与条之间飘。

| 页签 | 内核权重 | 上游标注「指令控制」 |
|---|---|---|
| 声音设计 | `VoiceDesign` 1.7B | **是** |
| 官方精品 | `CustomVoice` 1.7B | **是** |
| 语音克隆 | `Base` 1.7B / 0.6B | **否（留空）** |

> **实操结论：情绪是重点的句子，换模型比换措辞更彻底。**
> 把「悲痛绝望的大喊」这类台词交给**官方精品（1.7B）**或**声音设计**，
> 「语音克隆」留给「音色必须是他」的场景。克隆 + 强情绪的极限大概就是你听到的这个水平。

> **采样随机性仍然存在，但克隆页现在默认开启「音色稳定」。** 内核原本的
> `temperature=0.9 / top_p=1.0` 随机性偏大，同一句偶尔会抽到音色明显偏离参考的坏 take；
> 稳定模式改用 `0.35 / 0.85`，并在每段生成后和参考音频比一次说话人向量；
> 低于目标才额外生成候选并择优，频谱/基频检查继续兜底。固定 seed 只保证可复现，
> 不保证某个 take 一定像。想故意多试几种语气时可以在克隆页关掉它。

> **修正记录**：本文件曾写过「完整 ICL 会把指令压平」。**那条结论不成立，已撤下。**
> 两个原因：一是当时读的音色配置已经过期（用户中途把音色重建成仅向量）；
> 二是那个判断每条只跑了一两次，而真实噪声底是 ±2.5 半音，两三半音的差距读不出来。
> 前端那句橙色提醒也相应改掉了 —— 现在提示的是**标点与措辞**，不再指向克隆方式。


前端据此加了一条提醒：**在完整 ICL 下写了指令时，指令框下方会出现橙色提示**
（`syncInstructWarn()`），由 `tools/verify_instr_warn.js` 守着。

## 参考音频自动转写

参考文本在**完整 ICL 模式**下是必需项，而这玩意儿通常得靠人一句句听写。本项目把它自动化了：
在「参考文本」弹窗里有「自动转写」按钮（音色库卡片、新增音色弹窗、克隆页临时上传三处都有）。
**存进音色库时无论哪种模式都必填**（后端要用它保住切 ICL / 抽基因的能力）；
只有「临时上传 + 仅向量」这一次生成可以空着。已有音色可以在克隆页直接点「改参考文本」补。

- 引擎：**SenseVoice-Small**（`models/sensevoice-small/`，int8 约 0.24 GB，走 sherpa-onnx）；
- 依赖与权重都在包内，**开箱即用** —— `app/asr.py::available()` 会逐项检查，
  缺哪一样就报哪一样（缺 `sherpa_onnx`？缺权重目录？），界面据此把按钮置灰并说明原因，
  而不是做一个「点下去才报错」的按钮；
- 可用环境变量强制开关：`QWENSTUDIO_ASR=1` 强开、`=0` 强关（默认 `auto`）。

**它是打草稿的起点，不是终稿。** 实测识别会有同音字与标点出入：

| 参考音频真值 | 识别结果 | 集合重合度 |
|---|---|---|
| 小弟弟，有兴趣陪姐姐喝一杯吗？ | 小弟弟有兴趣陪姐姐喝一杯吗？ | 100% |
| 品质高的松茸都隐藏在土层之下，妈妈找寻着两天前亲手掩藏过的菌坑。 | 品质高的松茸都隐藏在土层之下，妈妈找寻了两天前亲手隐藏过的俊坑。 | 93% |
| 嘿嘿，为了此丹，大晋元婴中期修士都接连陨落，你说它效用如何？ | 哼为了此丹，大靖元因中期修饰都接连陨落，你说他效用如何？ | 81% |

典型的错法是同音字（大晋元婴→大靖元因、掩藏→隐藏）和丢逗号。所以转写完代码里**固定弹一条提示**，
让用户核对 —— 因为完整 ICL 模式下参考文本写错会直接污染输出。

速度：首次约 4.4 秒（含加载识别模型），之后每次 0.3–0.5 秒。

## 输出后处理（`app/postproc.py`）

合成完、写盘前统一整理一遍，**默认三项全关**，需要时在四个生成页的「输出后处理」折叠组里逐项开启。
来源是 omnivoice-studio 的 `remove_silence` / `fade_and_pad_audio`，搬过来时改了两处（见下）。

| 项 | 做什么 | 默认 |
|---|---|---|
| 去长静音 | 句中超过 `pp_mid_ms`（默认 500）的停顿压到 0.5 秒；首尾各留 0.1 秒 | 关 |
| 音量归一化 | 有声部分的 RMS 中位数拉到 −20 dBFS；峰值超 0.97 时软限幅 | 关 |
| 淡入淡出 | 首尾各 0.1 秒渐变 + 各 0.1 秒留白 | 关 |

顺序固定：**去静音 → 归一化 → 淡入淡出**。反过来会让补进去的空白污染响度统计。

两处刻意的偏离：

1. **不依赖 pydub。** 上游用 `split_on_silence` 逐 10 ms 建 `AudioSegment` 再 `+=` 拼接，
   30 秒音频要建上千个对象；这里用 numpy 一次算完帧能量再按区间切，同一条约 1–3 ms。
   判据保持一致（10 ms 帧、−50 dBFS 门限）。
2. **归一化目标改成固定值。** 上游是「按参考音频的 RMS 等比缩放」，保住了原音色的强弱关系，
   但不同音色之间仍然不齐 —— 各自的参考电平本来就不同。本工具要在多个音色/模式之间来回比，
   所以统一到 −20 dBFS。

**孤立尖峰走软限幅，不整体回缩**：实测 Qwen 产物的波峰因子能到 20–24 dB（正常语音 12–18），
99.9 分位 0.33 而峰值 0.56 —— 就是几个点特别大。按整条回缩等于为了几个样本扔掉 5–6 dB 响度，
多角色之间反而更不齐。尖峰占比 < 2% 时只压尖峰，否则才整体缩。

**流式（边生成边播）不做后处理**：音频块生成的同时就播出去了，收尾再剪静音会让「下载到的」
和「刚听到的」不是同一条。`done` 事件里 `postprocess.skipped = "stream"`，结果卡写「已跳过」。

统计（剪掉多少秒 / 实际增益）随 `result.postprocess` 返回，同时进合成记录 ——
「这条为什么比上次短一秒」只能靠它解释。开关与参数见 `/api/jobs` 的 `pp_*` 字段。

## 长文本与真进度（语音克隆页）

### 1. 不再有字数上限

克隆页输入框下面那行是**预估**，不是限制：`4 段 · 音频约 1.0 分钟 · 生成约 1.2 分钟`。
三个数全从服务端来 —— 语速是 `outputs/history.json` 的**实测中位数**（`limits.chars_per_sec`，
本机约 4.9 字/秒），克隆单段切分取自 `limits.clone_chunk_chars`（默认 600 字），
不是写死的常量。

「长文本」只有一个含义：**均衡切成多段，每段用同样的参数依次生成，最后拼成一条音频**
（剧本/官方段间插 `SCRIPT_GAP_SECS`，克隆段间默认只插 0.12 秒）。
切段是 `core.split_text`，clone / official / script 三条路共用
`core._run_pieces`，所以「切几段、怎么拼、进度怎么报」三个口径完全一致。

切段先按上限算出最少段数，再在理想切点附近找标点：优先句末标点，其次逗号等
停顿符，找不到合适标点才硬切。旧版从前往后贪心，用户那条 119 字实测文本会被切成
**80 + 37**：前半太长、后半重新起头，听起来就是「只有最后一句像」。现在克隆默认
**整段生成**（119 字 < 600 字阈值）；真超过 600 字时才按标点均衡切分，
不会留下一个只有十几字的尾巴。

### 音色稳定（克隆页默认开启）

克隆页第 2 张卡有一个「音色稳定（推荐）」复选框。开启时：

- 采样从内核默认的 `temperature=0.9 / top_p=1.0` 收到 `0.35 / 0.85`；
- 强制只使用 speaker embedding（`xvec_only=True`），避免完整 ICL 把参考音频的
  韵律和末字串进每一段；界面会同步锁定那个复选框；
- 每次任务生成一个主 seed，所有正常段共用同一个 seed；只有漂移重试才换 seed，
  实际值写进结果卡和合成记录；
- 每段生成后直接调用内核的 speaker encoder，和参考音频按 8 秒窗口计算 cosine；
  首条低于目标（默认 0.981），或与上一段不够连贯（默认低于 0.984）时，
  才额外生成一条候选，按「参考相似度 + 段间连贯度」择优，正常段不翻倍；
- 频谱质心、频谱平坦度、基频检查继续作为兜底；真实 speaker encoder 不可用时
  仍会换 seed 重生成一次；
- 结果卡与合成记录显示「候选择优 / 说话人相似度 / 段间音色连贯度 / 漂移重试」，
  流式记录也会保留实际参数。

这套择优按用户实测样本校准：旧坏段（前半）最低窗口相似度 0.9415，明显低于
0.972 的硬下限；94.9 秒长音频则从 0.984 缓慢掉到 0.971，属于模型自身的慢漂移。
speaker cosine 能筛掉「明显不是同一个人」的 take，但不能保证口型、呼吸和语速
像同一次连续录音。流式为了不让「刚听到的」和「最终文件」不一致，不做逐段替换式重试。

这也不是官方保证。上游仍有长文本语速漂移与采样随机性问题（Qwen3-TTS issues
#239 / #298 / #341 / #343），稳定模式只能把可控的几层收住；它不保证任意长文本
听起来像同一次连续录音。

系统设置里还有一项「克隆默认使用音色稳定」，它只决定新打开克隆页时的默认勾选；
单次生成页上的开关只影响这一次，两者分开保存。

- `clone` / `official` / `script` **都自动均衡切段**，多长都能念。
- **只有声音设计仍然限 2000 字**，而且不能放开：它每段都是一把**新嗓子**（上游没有固定 seed），
  切开再拼起来会变成两把不同的嗓子念同一段话 —— 那比拒绝生成更糟。
- 两道仍然存在的闸，都不是体验限制：
  - 预估生成时间 > 30 分钟时弹一次确认（一旦开跑，同机的其他生成都排在它后面）；
  - 预估**音频** > 4 小时（`MAX_AUDIO_SECONDS`）直接拒。24 kHz float32 = 96 KB/s，
    四小时音频光拼好的那条就 1.4 GB，拼接时峰值还是它的两倍 —— 这是内存保护，
    而且是在**开头**拒，不是跑到 90% 才 OOM。

### 2. 进度是真的，不是时间猜的

`core.synthesize(p, on_progress)` 逐段回调 `(done, total, stage)`，`server` 把它线性映射进任务进度，
并把 `pieces` / `piece` 一起返回。前端只要看到 `pieces > 1` 就直接用后端真值，不再走时间缓动：

| 场景 | 显示 |
|---|---|
| 长文本（多段） | `第 34/68 段` · `40%` · `已等待 96 秒 · 预计还要 2 分 12 秒` |
| 单段 / 短句 | 仍是「锚点用真的、段内按时间缓动」，封顶 89% |

为什么要分两种：单段时后端**确实**没有更细的信息（一次不可分割的模型调用），
这时时间缓动是唯一诚实的近似；而多段时手上有真话还去猜，只会出现「87% 停十分钟」。

### 3. 落盘改成原子写

`save_wav()` 先 `touch(exist_ok=False)` 抢名字（O_CREAT|O_EXCL，NTFS 上原子），
再写 `<name>.part<pid>_<tid>.wav`，最后 `os.replace`。原来「先 `while path.exists()` 选名字、
再 `sf.write`」是典型的查-写竞态 —— 只是以前写盘几乎总在 GPU 锁后面排队，没被撞见过。

## 音色基因（`.pt`）

一段参考音频的**预计算结果**。要复刻一个声音，得先把参考音频编码一遍 ——
取音色的指纹，再取整段音频的逐帧声学编码。这一步每次生成都做一遍是浪费，
所以做完就存下来，这就是「音色基因」。

**它省掉的是**：读 wav → 重采样 → 跑一遍 speaker 编码。

| | |
|---|---|
| 内容 | `ref_spk_embedding`（2048 维，音色指纹）+ `ref_code`（逐帧声学编码，随音频长度增长）+ 模式标志 + 参考文本 |
| 体积 | 16–51 KB，可忽略 |
| **什么时候生成** | **默认不生成**（只是缓存，不是音色的组成部分）；需要时点「生成音色基因」（单卡 / 侧栏批量），或 `POST /api/voices` 传 `prompt=true` |
| 什么时候失效 | **裁剪参考音频**时自动删除（编码对不上新音频了）；**覆盖保存**时同样先删旧基因再重抽 |
| 没有它会怎样 | 照常能用，只是每次生成都重新编码一遍参考音频 |

> 建基因要加载模型、几十秒起步，而省下的只是每次生成的一次 speaker 编码 ——
> 所以默认不建，只在「反复用、又走仅向量模式」的音色上手动补。

**加速只在「只用说话人向量」模式下兑现**（`xvec_only=True`）。参考文本必填之后，
新建音色默认走完整 ICL（`xvec_only=False`），这条加速默认用不上。
完整 ICL 模式下内核会在本次进程里自己缓存，但服务重启后仍要从 wav 重算 —— 这是
`_prime_prompt_cache()` 的取舍：只预热结构确定的那一种，宁可不加速也不构造错。

## 音色的「克隆方式」在哪看

「只用说话人向量」是**每个音色保存时记下**的一个属性（`voices/*.json` 的 `xvec_only`），
不是全局开关。早先界面从来不显示它 —— 数据一直在 `/api/voices` 里，只是没人读。
现在有三处能看到：

| 位置 | 显示什么 |
|---|---|
| 音色库卡片 | 右上角标签：`仅向量`（中性）/ `完整 ICL`（警示色） |
| 音色库筛选行 | `全部 N · 仅向量 N · 完整 ICL N`，可直接筛 |
| 侧栏「概览」 | `克隆方式：仅向量 N · 完整 ICL N` |
| 克隆页选中音色后 | 详情行写出「克隆方式」，并且**复选框会自动跟着音色走** |

> 只有需要「参考文本必须逐字写准」的完整 ICL 才用警示色 —— 仅向量只是中性标签，不该也跳出来抢注意力。

**修掉的一个坑**：克隆页生成时传的 `xvec_only` 来自那个复选框，而复选框不会跟着选中的音色变，
于是它会把音色自己的设置**悄悄覆盖掉** —— 一个存为「完整 ICL」的音色，用起来其实是「仅向量」。
现在选中音色时复选框会同步过去（仍可当场改，那是每一次生成的开关）。
同步**只在换了一个音色时做**，不是每次重画都做 —— 否则保存别的音色、刷新列表之后，
用户刚勾好的「这一次用向量」会被悄悄掰回音色设置。

**连带的第二个坑**：那个复选框原先被放在 `#c-pane-up`（临时上传）面板里面。
可正常用法是「用音色库的固化音色」，那整个面板是隐藏的 ——
**于是「仅向量 / 完整 ICL」在主要路径上根本无从切换**，同步过去也是同步给一个看不见的控件。
现已把它移出两个面板，无论用哪种音色来源都可见。

## 硬件自动适配

`app/hardware.py` 探测设备后给出一个 `Profile`，规则如下（`config.py` 里把 `DEVICE` / `DTYPE` /
`DEFAULT_SIZE` 设成具体值即可强制覆盖）：

| 决策 | 规则 |
|---|---|
| 后端 | `cuda` > `xpu` > `mps` > `cpu` |
| 精度 | 算力 ≥ 8.0 → `bfloat16`；≥ 6.0 → `float16`；其余 / CPU / MPS → `float32` |
| 默认规格 | 显存 ≥ 6 GiB → `1.7B`；否则 `0.6B` |
| 剧本单段上限 | ≥ 8 GiB → 150 字；≥ 6 → 100；≥ 4 → 70；≥ 2 → 50；CPU → 40 |

**本机实测档位（RTX 3060 Laptop 6 GB）：**

```
NVIDIA GeForce RTX 3060 Laptop GPU · 6.0 GiB · bfloat16 · 默认 1.7B
```

6 GB 是个临界档位：1.7B 跑得动，但长剧本会被自动切短分段，
且切换功能时一定会先卸载上一个模型。这是设计，不是故障。

### 实测性能（本机，clone / 1.7B / 24 字文本）

| 阶段 | 墙钟 | 音频 | 耗时 | RTF |
|---|---|---|---|---|
| 冷启动（加载 + CUDA graph 预热） | 15.2 s | 6.80 s | 14.80 s | 2.17 |
| 热路径 #1 | 5.0 s | 6.40 s | 4.20 s | **0.66** |
| 热路径 #2 | 5.1 s | 6.40 s | 4.20 s | **0.66** |

冷/热差 3.3 倍。热路径快于实时，长剧本批量生成没有压力。
模型加载本身只要 5.7–6.3 秒，剩下的时间花在 CUDA graph 捕获上（只做一次）。

复现：`runtime\python\python.exe tools\bench.py 御姐`

### 四层降级

1. GPU 加载失败 → 退到 CPU（慢，但能跑）
2. 生成 OOM → 卸载模型、清显存后**原样重试一次**（碎片型 OOM 常能救回来），状态会标为「完成（有提示）」
3. 推理内核 / 权重不匹配 → 用明确的错误信息代替堆栈
4. 参考音频转写不可用 → 明确说明原因，而不是静默失败

## 排错

出问题先点侧栏底部的**运行环境**芯片，那里有完整档位信息与针对性提示。常见情况：

| 现象 | 原因 / 处理 |
|---|---|
| 首次生成等了半分钟 | 正常，在加载权重。之后同规格会快很多 |
| 「完成（有提示）」 | 触发了 OOM 降级重试，结果是好的，但建议缩短分段 |
| 「缺少权重」 | `models/` 下对应目录不存在 |
| 转写按钮灰色不可用 | 悬停看 `title`，里面写明了缺哪一样（`sherpa-onnx` 或 `models/sensevoice-small/` 权重）；补上即可，或手工填参考文本 |
| 保存后没有「基因」徽章 | 正常，**基因默认就不生成**（只是可选加速缓存）。需要就点卡片上的「生成音色基因」，或侧栏批量 |
| 端口被占 | 用环境变量换端口：`set QWENSTUDIO_PORT=7877 && 启动程序.bat`（或改 `app/config.py` 的 `PORT`） |
| RTF 很高 | 首次调用含加载与 CUDA graph 预热（实测冷启动 RTF 2.17）；热路径应为 0.66 左右 |

跑一遍接口测试（需服务在运行）：

```
runtime\python\python.exe tools\smoke.py         # 约 62 项接口断言
runtime\python\python.exe tools\verify_split.py  # 切段 / 进度 / 原子落盘（不加载权重）
runtime\python\python.exe tools\bench.py 御姐    # 冷热路径与 RTF 基准
```

## 关于量化

**不建议为了省显存去量化 1.7B。** 克隆场景里：

- **音色几乎无损** —— speaker encoder 在 mmproj 里按 Q8_0 保存，音色路径基本不受影响；
- **韵律会塌** —— 主干被压缩，疑问句语调、句中停顿这类细节先崩。
  实测 Q4_K_M 会把 40 句疑问句里的 6 句语调压平（Q8_0 是 40/40）。

如果哪天真的需要，**直接上 Q8_0**，别用 Q4 系列。

更好的杠杆是**参考音频质量**（干净、5–12 秒、气口完整），
它对结果的影响远大于量化位数。

## 启动与端口

双击 `启动程序.bat` 即可，**浏览器会自动打开**（先派后台助手轮询端口，确认服务真的
起来了才开页签，不靠固定 sleep 猜时间）。不想自动开：`set QWENSTUDIO_NO_BROWSER=1`。

换端口：`set QWENSTUDIO_PORT=7877 && 启动程序.bat` —— 横幅和自动打开的地址都会跟着走。

**启动时会在后台把默认权重加载好**（6 GiB 档位上是 1.7B Base，约 18 秒加载 +
14 秒捕获 CUDA graph）。这段跑在后台线程里，端口先通、页面先能打开，所以不会
出现"打不开"；等横幅刷完几十秒，第一次点生成就是热的（实测首次生成 22 秒 → 7 秒）。

不想让它占着显存（比如这台机器要腾出来跑别的）：`set QWENSTUDIO_PRELOAD=0`。
想换成别的权重：`set QWENSTUDIO_PRELOAD_KIND=official` / `QWENSTUDIO_PRELOAD_SIZE=0.6B`。

```bat
更新代码.bat
```

它把代码 zip 盖到安装目录上，并清掉「新版本里已经不存在的旧文件」；
`voices/` `outputs/` `web/_uploads/` `models/` `runtime/` `vendor/` 一律不碰。
zip 会自动在同目录 / 下载 / 桌面里找最新的那个，也可以 `--zip` 指定。

启动后点左下角「运行环境」抽屉最下面一行，就是当前的代码版本号 ——
覆盖完看它，就知道生效了没。

版本号由 `tools\stamp_version.py` 按 git 写入 `app/buildinfo.py`。约定：

```
提交代码 → stamp_version.py --write → 把标记单独提交一次（**不要 amend**）
```

amend 会把上一次提交的哈希改掉，标记里那个哈希当场失效。

## 打包分发给别人

整个工作台自带运行时和权重，**解压到任何路径双击 `启动程序.bat` 就能跑** ——
代码里没有一处写死的绝对路径，运行时（WinPython）也没有 `pyvenv.cfg` / `._pth`
这类会绑死安装位置的锚点。

```bat
rem 先看一眼清单（不写盘）
runtime\python\python.exe tools\pack_release.py --list

rem 目录形态（拷进移动硬盘用这个）
runtime\python\python.exe tools\pack_release.py

rem 轻量包：不含权重
runtime\python\python.exe tools\pack_release.py --no-models

rem 单文件 zip / 分卷（微信那类 2–4 G 的限额只能用分卷）
runtime\python\python.exe tools\pack_release.py --zip
runtime\python\python.exe tools\pack_release.py --split 3800
```

| 形态 | 体积 |
|---|---|
| 完整（含 5 套权重） | 25.9 G |
| 不含权重 | 8.4 G |
| 完整 + zip（实测抽样压率推算） | 约 18 G |

**打包脚本只干两件事：挑对文件、别把主人的东西带出去。**
下面这些**永远不进包**（它们是使用痕迹，不是软件本体）：

```
voices/          自己录/存下来的音色
outputs/         生成结果与 history.json
web/_uploads/    界面上传的临时音频
web/_preview/    官方说话人试听缓存
.workbuddy/      项目笔记
```

包里会另附两份东西：`首次运行-必读.txt`（给接收方看的，含显卡要求、常见问题）
和 `打包清单.txt`（含了什么、没含什么、各部分多大）。

**打包后务必自测一遍再发出去**，用硬链接建副本，秒级完成、不占额外空间：

```bat
runtime\python\python.exe tools\pack_release.py --hardlink --name _selftest
```

然后把它挪到项目**外面**的另一个路径，双击 `启动程序.bat` 看能不能起来。
（硬链接版**只能自测**：文件本体还在你这块盘上，发给别人是断链。）

## 技术栈

- 推理内核：[faster-qwen3-tts](../Qwen3TTS（千问）/Qwen3TTS_Pro/faster-qwen3-tts-main)（CUDA Graph 加速）
- 模型：Qwen3-TTS-12Hz 系列，Apache-2.0，24 kHz 输出，12 Hz tokenizer，10 语种
- 后端：FastAPI + uvicorn（已随运行时提供，零新增依赖）
- 前端：原生 HTML/CSS/JS 单文件，无构建步骤
- 音频：numpy + soundfile；格式转码走 vendor 里的 ffmpeg/sox
